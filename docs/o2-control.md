# 02の登録・連携管理

管理画面の「教育・媒体登録」→「SNS連携・ログイン情報」上部で操作する。

## 動作

店舗の保存済み02ログイン情報で5分ごとに連携申請を取得する。確認失敗は「申請なし」に置き換えず、前回の申請と最終成功時刻を残す。未照合の申請は承認できない。照合には在籍中のセラピストの02ユーザー名を使う。承認直前に申請を取り直し、02の承認APIの成功、申請の消失、在籍一覧への追加を確認して完了にする。結果不明時は自動再送しない。

店舗操作は有効なログインと `can_manage_store` の確認が必要。ブラウザから状態テーブルへ直接更新はできない。内部処理はVaultの専用鍵で認証し、店舗単位のロックで同時実行を防ぐ。

在籍中の作成済みアカウントを順番に確認する。各アカウントは原則1時間以上間隔をあける。作成・認証・審査・連携申請は別の状態であり、メール到着だけでは完了扱いにしない。

## 初回のGmail接続

認証メールの**転送先のGmailアカウント**で行う。ChatGPTへのGmail接続だけでは、ZR OSのサーバーに継続的な読み取り権限は渡らない。

画面の「Gmail認証メールの連携設定」で専用コードをコピーし、そのGoogleアカウントのGoogle Apps Scriptに貼り付けて `setupO2MailSync` を1回実行し、Gmailの読み取りを許可する。その後は毎分動く。02の認証メールのみを転送し、他のメールは送らない。専用鍵はScript Propertiesに保存され、ZR OS側はハッシュのみを保存する。

転送前の宛先をTo・X-Original-To等から受け取り、02の登録メールと照合する。GmailのAuthentication-Resultsでm-sns.netのDKIM成功を確認でき、10分以内、登録開始後、候補コードが1つ、対象者が1人に決まる場合だけ使用する。不一致・期限切れ・不明な送信元は使用しない。受信済みメッセージは記録し、別の登録に再利用しない。認証コードと一時Cookieは一般ユーザーが読めない領域に保存し、使用後・期限切れ時に消す。本文とコードはログに出さない。

Gmail側は、対象の登録処理より先にメールが届いても取りこぼさないよう、対象処理にひも付いたメールIDだけを送信済みにする。

## 新規登録

SNS設定の登録メール・ユーザー名・パスワード、HPの公開プロフィールを使う。Gmailとの直近の通信が確認できない間は開始しない。現時点の登録エリアは艶華（宮城）のみ。公開中・写真あり・年齢18歳以上が条件。

登録画面の既知の入力項目・地域選択を確認して送る。未対応の画面や追加の確認がある場合は停止する。登録・認証の送信後に結果が不明なら再送しない。認証後は02運営の審査待ちになる。審査後の確認に成功すると、新規登録で開始したアカウントだけHPプロフィール・写真と店舗連携申請を進める。店舗側の承認は所有者の操作を待つ。

既存アカウントの「HPのプロフィール・写真を反映」は手動操作で開始する。既存の選択値・他SNSのリンク・紹介文等は保存前に読み取り、HPに値がある対応項目だけを更新する。画像取得先と容量を制限しているため、未対応の保存先はエラーになる。

## 検証と残る確認

店舗ログイン、申請0件の取得、セラピストログインと状態確認は実アカウントで確認済み。新規登録・メール認証・実際の連携申請の承認・プロフィール書き込みは、対象の実データでの確認が必要。試験用の架空アカウントは作成していない。

メールはm-sns.netの送信・DKIMを前提としている。実際の認証メールが別ドメインで配信される場合は、実メールで確認したうえで送信元判定を追加する必要がある。Gmail側の許可はユーザーによる初回設定が必要。
