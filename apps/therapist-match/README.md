# Bloom（仮称）セラピスト登録サービス（試作）

メンズエステのセラピストが1分で登録し、今月受け入れているお店を一覧で比べて応募できるサービスの試作。
運営のコーチが登録から在籍1か月後までマンツーマンで伴走する（お店選び・体験入店の振り返り・写メ日記の添削・リピートづくり）。
キャスカンとは独立したサイトで、公開するときは Vercel の別プロジェクト（ルートディレクトリ `apps/therapist-match`）にする。

## 画面

セラピスト側

- `/` 広告LP：コーチングを前面に出した訴求、登録から在籍までの流れ、収入の目安の計算、1か月のレッスン、よくある質問
- `/register` 3ステップ・約1分の登録（ニックネーム・年齢・エリア → 経験・ペース・目標月収 → 連絡先・18歳以上の確認）
- `/stores` 受け入れ中のお店の一覧（エリア・こだわり条件・受け入れ枠で絞り込み、並べ替え）
- `/stores/:id` お店の詳細（取り分・保証・平均日給、コーチの取材コメント、週3日の収入の目安）
- `/me` マイページ（担当コーチ、次にやること、応募したお店の進み具合、目標月収に必要な本数、レッスンの進み具合）

運営側（`/admin`）

- ダッシュボード：今日やること（コーチ未定の新規登録・面談・体験入店の振り返り）、段階ごとの人数、コーチの担当人数
- 登録者：段階・担当コーチ・応募先の状況を更新（マイページに反映）
- 掲載店舗：プラン別の掲載料、受け入れ枠、応募・在籍数、掲載状態、掲載審査の基準
- 収支シミュレーター：広告費・登録単価・歩留まり・店舗数・掲載料・コーチ体制から、黒字化する月・必要な運転資金・1入店あたりの獲得コストを計算（`src/lib/simulator.ts`）
- 立ち上げチェック：公開前に決めること（事業の形・届出・年齢確認・掲載審査・個人情報）

## 収益モデルの前提（法律まわり）

- 売上はお店からの**定額の掲載料だけ**。入店人数やセラピストの売上に連動する報酬（成果報酬・スカウトバック）は受け取らない
- セラピストからは登録料・講習料・紹介料を取らない
- 性風俗店は扱わない。性風俗の仕事への紹介・募集は職業安定法63条の対象で、2025年6月施行の改正風営法では性風俗店がスカウトに紹介の報酬を払うことも禁止された。Web・AIに置き換えてもこの部分は避けられない
- 運営が特定の人を特定のお店にあっせんすると職業紹介（許可制）、雇って送り出すと労働者派遣（許可制）。試作では「本人がお店に応募する＋運営はコーチング」の形にしている
- 登録者の情報を集めて求人を届けるので、特定募集情報等提供事業の届出が必要になる見込み
- 詳細は管理画面の「立ち上げチェック」。公開前に弁護士・社労士の確認を取ること

## データ

- 試作のため、データはブラウザの localStorage にだけ保存する（`src/hooks/useApp.tsx`）。お店・登録者はすべてサンプル（`src/data/seed.ts`）
- 本番化するときは Supabase にテーブル（stores / therapists / applications / coaches / lessons_progress）を作り、セラピストのログインは LINE ログインにする想定

## 開発

```sh
npm install
npm run dev      # http://localhost:8082
npm run build    # 型チェック + ビルド
npm test         # 収支シミュレーター・収入の目安のテスト
```

`VITE_ROUTER=memory npm run build` にすると、URLを持てない埋め込みプレビュー用にメモリ上のルーターでビルドする。
